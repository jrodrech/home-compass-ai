# HomeCompass AI - Domain Model

## Purpose

This document describes the conceptual domain model of HomeCompass AI.

It defines the main business concepts, their relationships, and the responsibilities they represent.

The domain model is intentionally technology-independent. It should describe the business problem before considering database tables, API endpoints, or implementation details.

This document is a living artifact and should evolve as the understanding of the product grows.

---

# Domain Overview

HomeCompass AI is a multi-user SaaS platform that helps people make better real estate decisions by understanding their personal circumstances, preferences, and constraints.

The central domain relationship is:

```
User
 |
 |
creates and owns
 |
 v
Buyer Profile
 |
 |
 evaluates
 |
 v
Property
 |
 |
produces
 |
 v
Recommendation
```

The system does not evaluate properties in isolation.

A property becomes meaningful only when evaluated against a specific buyer context.

# Core Entities

## UserAccount

### Purpose

Represents the identity of a person registered in the platform.

### Responsibilities

- Account ownership
- Authentication identity
- Access management
- Ownership of personal information

### Relationships

```
UserAccount
     |
     | 1..*
     |
     v
BuyerProfile
```

### Notes

A UserAccount represents the person using the platform.

It does not contain detailed real estate preferences.

---

# BuyerProfile

## Purpose

Represents a user's real estate search context.

The BuyerProfile captures the information necessary to understand what kind of property would improve that person's life.

### Responsibilities

- Define housing needs
- Store financial constraints
- Represent lifestyle preferences
- Capture accessibility requirements
- Provide context for recommendations

### Relationships

```
UserAccount

     |
     |
     v

BuyerProfile

     |
     |
     evaluates

     v

Property
```

### Possible Future Areas

The BuyerProfile may eventually contain:

- FinancialAssessment
- AccessibilityProfile
- LifestylePreferences
- FamilySituation
- LocationPreferences
  These concepts should be introduced only when their business meaning is clear.

---

# Property

## Purpose

Represents a real estate asset that can be analyzed by the platform.

### Responsibilities

- Store property characteristics
- Provide information required for evaluation
- Participate in matching decisions

### Possible Information

- Location
- Price
- Property type
- Size
- Bedrooms
- Bathrooms
- Amenities
- Accessibility characteristics
- Financial considerations

### Important Principle

A Property does not have an intrinsic recommendation value.

Its suitability depends on the BuyerProfile evaluating it.

---

# Match

## Purpose

Represents the compatibility relationship between a BuyerProfile and a Property.

A Match answers:

> "How suitable is this property for this specific buyer?"

### Responsibilities

- Calculate compatibility
- Identify positive factors
- Identify concerns
- Explain trade-offs

### Relationship

```
BuyerProfile

       +

Property

       |
       v

     Match
```

### Example

```
BuyerProfile:
Remote worker
Needs accessibility
Maximum payment: $2300/month

Property:
Miami condo

Match:
85%

Positive:
- Fits payment
- Elevator available
- Close to services

Concern:
- Higher HOA
```

---

# Recommendation

## Purpose

Represents a ranked suggestion generated by the system.

A Recommendation is the user-facing result of the matching process.

### Responsibilities

- Present suitable properties
- Explain selection reasons
- Support decision-making

### Relationship

```
BuyerProfile

      |
      |
evaluates multiple properties

      |
      v

Recommendation List
```

# Supporting Domain Concepts

## Recommendation Engine

### Purpose

Business capability responsible for generating matches and recommendations.

It combines:

- Domain rules
- Scoring algorithms
- Future ML.NET models
  It should produce explainable results.

---

## AI Assistant

### Purpose

Conversational capability that helps users express their needs naturally.

Responsibilities:

- Understand user language
- Extract preferences
- Help build or refine BuyerProfiles
  The AI Assistant does not directly decide recommendations.

# Domain Boundaries

The initial modular monolith will organize capabilities around business concepts.

Conceptual modules:

```
HomeCompass

├── User Management
│
├── Buyer Profiles
│
├── Property Management
│
├── Recommendation Engine
│
└── AI Capabilities
```

Each module should maintain clear responsibilities.

Future extraction into independent services should be possible if business requirements justify it.

---

# Design Principles

## 1. The user is the center of the system

The purpose of the platform is not property catalog management.

The purpose is helping people make better decisions.

---

## 2. Recommendations must be explainable

The system should communicate:

- Why a property was recommended.
- Which needs it satisfies.
- What trade-offs exist.

---

## 3. AI enhances understanding, not business authority

The AI Assistant helps interpret human needs.

The Recommendation Engine applies business reasoning.

---

## 4. Model the business, not the database

Entities should represent real business concepts.

Database design should follow domain understanding, not drive it.

# Evolution Process

When introducing a new domain concept:

1. Discuss its business meaning.
2. Update the Ubiquitous Language.
3. Update this Domain Model.
4. Evaluate relationships with existing concepts.
5. Implement the code representation.
   The domain model is a living artifact that evolves with the product.
